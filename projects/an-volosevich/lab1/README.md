# Лабораторная работа №1 — Развёртывание и эмпирический анализ LLM

## Описание задания

Три LLM из разных семейств (Qwen, Llama, Mistral) развёрнуты с OpenAI-совместимым REST API и
протестированы на трёх задачах на русском языке (генерация, классификация, извлечение) в двух
режимах: **A** — дефолты движка, **B** — тюнинг гиперпараметров. Дополнительно — 8 задач по
программированию на английском с проверкой скрытыми тестами.

## Коротко о результатах

| Модель | Режим | P1 письмо | P2 классиф. | P3 извлеч. | Код | Генерация, ток/с | Ответ, с |
|---|---|---|---|---|---|---|---|
| Llama-3.1-8B | A | 2.0 | 3.0 | 3.0 | 5/8 | **108** | 2.3 |
| Llama-3.1-8B | B | **3.0** | 2.0 | 3.0 | 5/8 | 107 | 1.7 |
| Ministral-3-8B | A | **3.0** | 4.0 | 4.0 | 6/8 | 99 | **1.6** |
| Ministral-3-8B | B | **3.0** | 4.0 | 4.0 | **7/8** | 98 | **1.6** |
| Qwen3.8 REAP-256 | A | 1.0 | **5.0** | **4.3** | **7/8** | 35 | 36.9 |
| Qwen3.8 REAP-256 | B | 1.3 | **5.0** | 4.0 | 6/8 | 34 | 13.1 |

P1–P3 — оценка слепого LLM-судьи (1–5, среднее по 3 повторам); код — решённые задачи из 8.

- **Ministral-3-8B** — лучший баланс: 3–4 балла на русских задачах, 7/8 на коде, ~100 ток/с.
- **Qwen3.8 REAP-256** — лучшая на классификации, извлечении и коде, но не пишет по-русски и
  в 3 раза медленнее при 12× большем объёме весов.
- **Llama-3.1-8B** — самая быстрая и самая слабая.
- **Тюнинг** (`temperature=0`) делает структурные ответы детерминированными, но закрепляет
  систематические ошибки; для reasoning-модели решающий параметр — `max_tokens`.

## Стенд

**Железо:** Ryzen 9 9950X, 64 GB DDR5-6000, RTX 5070 12 GB, NVMe SSD.

| Семейство | Модель | Квантование | Размер | Размещение |
|---|---|---|---|---|
| Qwen | Qwen3.8-Flash-Next **REAP-256** (MoE 116.5B, 256 из 512 экспертов) | UD-Q3_K_XL | 57.7 GiB | GPU + RAM + SSD |
| Llama | Llama-3.1-8B-Instruct | Q4_K_M | 4.6 GiB | GPU |
| Mistral | Ministral-3-8B-Instruct-2512 | Q4_K_M | 4.8 GiB | GPU |

| Инструмент | Назначение |
|---|---|
| **llama.cpp b11524**, сборки `ubuntu-cuda-12.8-x64` + `cudart` | готовые бинарники с CUDA-рантаймом: без сборки, CUDA Toolkit и root; CUDA 12.8 поддерживает Blackwell (RTX 50xx) |
| `llama-server` | OpenAI-совместимый REST: `/v1/chat/completions`, `/tokenize`, `/health`; шаблоны чата (Jinja) из GGUF, рассуждение Qwen — в `reasoning_content` |
| `llama-fit-params`, `--fit` | расчёт раскладки весов MoE между VRAM и RAM |
| `llama-bench` | подбор числа CPU-потоков |
| GGUF с Hugging Face | Unsloth Dynamic (Qwen), bartowski (Llama), официальный mistralai (Ministral) |
| Python 3.14 + venv | клиент на `urllib`, песочница для кода (`subprocess` + `resource`), `matplotlib`, `pytest` |

llama.cpp выбран из-за модели на 116B: он считает часть экспертов MoE на CPU прямо из RAM
(`--fit` / `--n-cpu-moe`) и держит таблицу эмбеддингов на SSD через mmap. vLLM и SGLang рассчитаны
на веса в VRAM — их выгрузка в RAM лишь подкачивает веса на GPU и для такой модели слишком медленна.

## Параметры запуска

```bash
llama-server -m qwen38/Qwen3.8-Flash-Next-UD-Q3_K_XL-reap256-00001-of-00002.gguf \
  -c 16384 --parallel 1 -fa on --fit on -t 12 --chat-template-kwargs '{"reasoning_effort":"low"}'
llama-server -m llama31-8b/Meta-Llama-3.1-8B-Instruct-Q4_K_M.gguf     -c 8192 -ngl 99 -fa on
llama-server -m ministral3-8b/Ministral-3-8B-Instruct-2512-Q4_K_M.gguf -c 8192 -ngl 99 -fa on
```

- **`--fit on`** — плотные веса и эксперты слоёв 0–4 на GPU (~10.5 GB), эксперты 43 слоёв в RAM.
- **mmap** — таблица `per_layer_token_embd` (26.8 GiB, 46 % файла) читается по нескольку строк на
  токен и остаётся на SSD; в RAM активно ~22 GiB экспертов.
- **`-t 12`** — по `llama-bench`: 8 → 31.0, **12 → 33.3**, 16 → 32.1 ток/с.
- **`reasoning_effort: low`** — параметр шаблона чата (не сэмплинга), одинаков в A и B.

| Параметр | A (дефолт) | B: P1 | B: P2, P3 | B: код |
|---|---|---|---|---|
| `temperature` | 0.8 (Qwen 1.0) | **0.7** | **0** | **0** |
| `top_p` | 0.95 | **0.9** | **1.0** | **1.0** |
| `top_k` | 40 (Qwen 20) | 40 | **1** | **1** |
| `repeat_penalty` | 1.0 | **1.1** | 1.0 | 1.0 |
| `max_tokens` | без лимита | **1024** | **1024** | **8192** |

Значения Qwen в режиме A — из метаданных GGUF. `cache_prompt: false`, перед замерами — прогрев.
Отдельный эксперимент **B_long** (только Qwen, C3 и C8): параметры B, контекст 65 536,
`max_tokens=32768`.

## Методика

| Задача | Содержание | Оценка |
|---|---|---|
| **P1** письмо (рус.) | письмо о задержке заказа: 9 фактов, 120–180 слов, без выдумок | 7 авто-проверок + судья |
| **P2** классификация (рус.) | 9 обращений → `Billing` / `Tech support` / `Sales`, только JSON | доля верных меток + судья |
| **P3** извлечение (рус.) | описание смартфона → JSON из 10 полей; «1 год» → 12 мес., вес отсутствует | доля верных полей + судья |
| **C1–C8** код (англ.) | палиндром, интервалы, римские числа, топ-k слов, `k[...]`, скобки, минимальное окно, калькулятор | 5–11 скрытых тестов, код в изолированном процессе |

P1–P3 — 3 повтора (54 ответа), C1–C8 — один прогон на режим (48 ответов; в B декодирование
детерминировано). Судья оценивает ответы P1–P3 вслепую: они обезличены и перемешаны
(`results/judge/`).

## Результаты работы

### P1 — письмо клиенту

Судья, A → B: **Llama** 2.0 → 3.0 · **Ministral** 3.0 → 3.0 · **Qwen** 1.0 → 1.3.

- **Llama** пропускает срок «3 рабочих дня» в 3 из 6 писем, пишет с англицизмами (`slightly`,
  `SMALL`, `soon`), а в режиме A додумывает условия (галлюцинации в 2 из 3 писем против 1 из 3 в B):
  промокод действует *«на любой покупку, превышающую 1000 рублей»*, а клиентку успокаивает фраза
  *«На нашей стороне все нормально»*. Однажды вместо срока — *«[предполагаемая дата поставки]»*.
- **Ministral** пишет грамотнее всех, но в 5 из 6 писем портит название магазина, причём в обоих
  режимах: *«**Команда Техн[TOOL_CALLS]�ир.**»* — в текст протекает служебный токен вызова
  инструментов и обрывок UTF-8; в других письмах — *«Технчиер»*, *«Техномври»*, *«Техновин»*.
- **Qwen** не написал ни одного письма на русском. Задачу он понимает — рассуждение точно
  пересказывает промпт: *«The user wants me to write a polite email from an online store "ТехnoMIR"
  to a customer Anna Sergeevna Petrova about a delayed order…»*. А лучший из ответов выглядит так:

  > Прsubject: Аtrасo в su pedido №48213 — и lo sentimos mucho
  >
  > Estimada Anna Sergeevna Petrova: Nos dirigimos a usted con una noticia importante…

  В остальных прогонах — пустые ответы и борьба с собой: *«Wait — I need to rewrite this entirely
  in Russian»*, *«NO NO NO. RUSSIAN. Cyrillic alphabet.»*.

Авто-проверки фактов этого не видят: у Llama они дают 0.95–1.00 при оценке судьи 2–3.

### P2 — классификация обращений

Судья, A → B: **Llama** 3.0 → 2.0 · **Ministral** 4.0 → 4.0 · **Qwen** 5.0 → 5.0.

- **Llama** при `temperature=0` три раза подряд выдала одинаковые 10 меток на 9 обращений — по
  циклу Billing → Tech support → Sales, а не по смыслу (5/9). При температуре по умолчанию один из
  трёх ответов верный: жадное декодирование не исправляет ошибку, а делает её воспроизводимой.
- **Ministral** и **Qwen** — 9/9 во всех прогонах; Ministral теряет балл только за обёртку
  ```` ```json ````.

### P3 — извлечение полей

Судья, A → B: **Llama** 3.0 → 3.0 · **Ministral** 4.0 → 4.0 · **Qwen** 4.3 → 4.0.

Все модели верно ставят `weight_g: null` и пересчитывают «1 год» в 12 месяцев — галлюцинаций
значений нет.

- **Llama** в режиме A однажды вместо JSON написала Python-скрипт с регулярными выражениями — с
  честным комментарием `weight_g_pattern = r''  # Не знаю, как извлечь вес из описания, поэтому
  оставлю это пустым`. Скрипт к тому же нерабочий. В режиме B — верный JSON, но с пояснениями после
  него.
- **Ministral** — верный JSON во всех прогонах.
- **Qwen** — верный JSON; в одном ответе значение сменило язык: `"color": "марсианский orange"`.

### C1–C8 — программирование на английском

| Модель | Решено, B | Решено, A | Тесты, B | Тесты, A | Генерация, ток/с | Ответ, с |
|---|---|---|---|---|---|---|
| Llama-3.1-8B | 5/8 | 5/8 | 72 % | 78 % | **115.8** | **1.5** |
| Ministral-3-8B | **7/8** | 6/8 | **91 %** | 77 % | 105.6 | 1.8 |
| Qwen3.8 REAP-256 | 6/8 | **7/8** | 75 % | **88 %** | 34.8 | 68.7 |

![Задачи по программированию](source/results/plots/code_heatmap.png)

- **Llama** ошибается в сортировке `top_k_frequent_words` в обоих режимах; при `temperature=0`
  ломает `decode_string`, зато решает `min_window`, на которой падает в режиме A.
- **Ministral** в режиме A не справляется с вложенностью `k[...]` (`3[a2[c]]` → `acac`), в B —
  решает всё, кроме калькулятора.
- **Qwen** решает почти всё, но ценой времени (69 с на задачу) и с двумя странными провалами:
  - **C3, римские числа.** Вместо алгоритма модель выписывает числа подряд и ошибается:
    *«190-193: CM, CMI, CMII, CMIII»*; в режиме B обрывает генерацию посреди рассуждения
    (*«Wait, I need»*) через 4 143 токена без кода.
  - **C8, калькулятор.** В режиме A рассуждение зацикливается и заполняет весь контекст 16k (470 с),
    в режиме B не укладывается в 8192 токена.
- **C8 не решила ни одна модель** — Ministral и Llama в B проходят 3/11 и 2/11 тестов.

**Эксперимент B_long** (Qwen, контекст 65k, `max_tokens=32768`):
- **C3 решена** — 7/7 за 1 109 токенов (34 с).
- **C8 — нет.** 16 минут рассуждений с верным решением, в которых модель **69 раз** объявила
  *«Let me write the final code»*, каждый раз возвращаясь к перепроверке (*«Actually, let me also
  think…»*).
- **C3 в B и B_long дала разный результат при одинаковом сэмплинге.** Контекст 65k меняет раскладку
  весов между GPU и CPU, а с ней — численные результаты и весь ход рассуждения. `temperature=0`
  воспроизводим только при той же конфигурации запуска.

### Влияние режима на длину и стабильность

![Длина ответа](source/results/plots/tokens_breakdown.png)
![Стабильность](source/results/plots/stability_heatmap.png)

- **Длина.** Тюнинг сокращает ответы, где модель «болтает»: Llama P3 362 → 182 токена, Qwen P1
  3163 → 657. У Qwen рассуждение занимает 63–98 % токенов.
- **Стабильность.** При `temperature=0` P2/P3 дают один и тот же ответ во всех повторах. Ministral
  почти детерминирован и в режиме A. «2 из 3» у Qwen P1 A — два одинаково пустых ответа.
- **Петли.** В режиме A (`temperature=1.0`) рассуждение Qwen вырождается: *«I'll write
  "Иnfractions"»* — **164 раза** подряд, *«Actually, let me use "U."? Hmm.»* — 87 раз; 53 %
  повторяющихся 3-грамм. В режиме B (`repeat_penalty=1.1`) — 14 %.

## Выводы

1. **Эффект гиперпараметров зависит от задачи.** `temperature=0` даёт детерминизм и убирает дрейф
   формата на структурных задачах, но закрепляет систематические ошибки (Llama P2). На генерации
   тюнинг снижает галлюцинации Llama и длину рассуждений Qwen.
2. **Для reasoning-модели главный параметр — `max_tokens`.** Без лимита Qwen тратит до 16 тыс.
   токенов и зацикливается; с лимитом — быстрее, но может не успеть ответить. Больший бюджет
   помогает не всегда: на C8 не хватило и 32 тыс. токенов — модель не может закончить перепроверку.
3. **REAP-прунинг, вероятно, сломал русский язык у Qwen:** значимость экспертов считалась на коде
   и агентных задачах. Русский модель понимает (P2, P3), но писать на нём не может.
4. **Квантованная Ministral портит кириллицу** (служебные токены, битый UTF-8) независимо от
   сэмплинга.
5. **Авто-метрики завышают качество текста** (Llama P1: 0.95–1.00 против 2–3 у судьи) — для
   генерации нужен судья.
6. **Модель 8B на GPU (~100 ток/с) выгоднее 116B MoE с экспертами в RAM (34 ток/с)** — на этих
   задачах большая модель не окупает ресурсы.

## Инструкция по запуску

1. Скачать llama.cpp [b11524](https://github.com/ggml-org/llama.cpp/releases/tag/b11524)
   (`llama-…-ubuntu-cuda-12.8-x64` и `cudart-…-cuda-12.8-x64`) в `~/llms/llama.cpp/llama-b11524/`.
2. Скачать модели в `~/llms/models/` (пути — в `source/config.py`):
   `AnonimousA/Qwen3.8-Flash-Next-REAP-256-duo-GGUF` → `qwen38/`,
   `bartowski/Meta-Llama-3.1-8B-Instruct-GGUF` (Q4_K_M) → `llama31-8b/`,
   `mistralai/Ministral-3-8B-Instruct-2512-GGUF` (Q4_K_M) → `ministral3-8b/`.
3. Окружение и прогон (из корня репозитория):
   ```bash
   python3 -m venv .venv && source .venv/bin/activate
   pip install -r projects/an-volosevich/lab1/source/requirements.txt
   cd projects/an-volosevich/lab1/source
   python -m pytest -q          # тесты оценщиков и эталонные решения
   python run_bench.py          # P1–P3 → results/runs.jsonl
   python run_code.py           # C1–C8 → results/code_runs.jsonl
   python run_code.py --long --models qwen3.8-flash-next-reap256 --problems C3_int_to_roman C8_calculator
   python analyze.py            # results/summary.md
   python judge.py prepare      # обезличенные ответы для судьи → results/judge/
   python judge.py report       # после оценки: results/judge/report.md
   python code_eval.py          # results/code_summary.md
   python visualize.py          # results/plots/
   ```
