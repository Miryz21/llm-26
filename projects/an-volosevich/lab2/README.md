# Лабораторная работа №2 — RAG-агент по научным статьям

## Описание задания

RAG-агент отвечает на вопросы (на русском или английском) по четырём статьям arXiv о
диффузионных моделях: находит релевантные фрагменты и формирует ответ LLM с цитатами —
статья, раздел, страница, сниппет, ссылка.

## Коротко о результатах

| Конфигурация | Чанков | ru R@5 | ru MRR | en R@5 | en MRR |
|---|---|---|---|---|---|
| **итоговая**: markdown 800/100, hybrid bge-m3, перевод запроса | 92 | **0.929** | 0.825 | 0.881 | 0.820 |
| docling-сплиттер вместо markdown | 99 | 0.889 | **0.845** | 0.889 | **0.844** |
| без перевода запроса | 92 | 0.833 | 0.710 | 0.881 | 0.820 |
| без заголовков в тексте чанка | 88 | 0.762 | 0.693 | 0.810 | 0.675 |

24 вопроса на двух языках, k = 5; полная таблица — в [разделе «Оценка retrieval»](#оценка-retrieval).

- **Заголовок в тексте чанка** («название статьи | раздел») — самый сильный параметр: без него
  MRR падает с 0.82 до 0.68–0.69.
- **Перевод русского вопроса на английский** (LLM, медиана 238 мс) поднимает MRR русских вопросов
  с 0.71 до 0.83 — до уровня английских.
- **Hybrid** (dense + 0.3·sparse bge-m3) — лучший баланс: sparse находит чуть больше в топ-5,
  но реже ставит нужный фрагмент первым.
- **docling-сплиттер** даёт лучший MRR на обоих языках; разница с итоговой — около одного вопроса
  из 24.
- **Формулы**: 3 из 4 выносных формул распознаны точно, строчные (inline) теряют двумерную
  вёрстку — см. [проверку парсинга формул](#проверка-парсинга-формул).

## Корпус и вопросы

| Статья | arXiv | Страниц |
|---|---|---|
| Direct3D: Scalable Image-to-3D Generation via 3D Latent Diffusion Transformer | [2405.14832v2](https://arxiv.org/abs/2405.14832v2) | 15 |
| ViewCrafter: Taming Video Diffusion Models for High-fidelity Novel View Synthesis | [2409.02048v1](https://arxiv.org/abs/2409.02048v1) | 13 |
| DreamPainter: Image Background Inpainting for E-commerce Scenarios | [2508.02155v1](https://arxiv.org/abs/2508.02155v1) | 13 |
| Preserving Product Fidelity in Large Scale Image Recontextualization with Diffusion Models | [2503.08729v1](https://arxiv.org/abs/2503.08729v1) | 12 |

Итого 53 страницы. Версии статей зафиксированы, файлы проверяются по sha256.

[`questions.json`](questions.json) — 24 вопроса, у каждого формулировка на русском и английском,
1–3 дословные фразы-доказательства из статьи (эталон для retrieval), ключевые факты и эталонный
ответ:

- 18 вопросов по тексту: архитектура, гиперпараметры, данные, результаты, абляции, сравнение статей;
- 4 вопроса по выносным формулам и 2 — по строчным; фразы-доказательства для них взяты из
  LaTeX-исходников статей, поэтому вопросы одновременно проверяют качество парсинга.

## Конвейер

| Шаг | Файл | Что делает | Библиотеки |
|---|---|---|---|
| 1 | `data_acqusition.py` | скачивание PDF и метаданных arXiv | `pooch`, `arxiv` |
| 2 | `data_parsing.py` | PDF → Markdown + JSON документа | `docling` |
| 3a | `data_chunking.py` | разбиение на чанки | `langchain-text-splitters`, `docling` |
| 3b | `build_index.py` | dense- и sparse-эмбеддинги | `FlagEmbedding` (bge-m3) |
| 4 | `load_to_vector_store.py` | загрузка в коллекцию Qdrant | `qdrant-client` |
| 5 | `retriever.py`, `evaluate.py` | поиск, перевод запроса, метрики | `qdrant-client`, `openai` |
| 6 | `rag.py` | ответ LLM с цитатами | `openai` |
| — | `orchestrator.py` | запуск шагов 1–6 по порядку | `typer` |

Каждый шаг пишет результат в `data/` и при повторном запуске переиспользует актуальный результат:
пересборка происходит только при изменении параметров или входных файлов. Параметры задаются
флагами CLI или переменными окружения `RAG_*` (`pydantic-settings`).

### 1. Данные

Статьи и метаданные (название, авторы, даты) скачиваются с arXiv в `data/pdf/` и
`data/metadata.json`. Скачанный файл принимается, только если его sha256 совпадает с эталоном;
повреждённый или недостающий файл скачивается заново.

### 2. PDF → Markdown

docling размечает страницу моделью вёрстки, поэтому колонтитулы, номера страниц, боковая метка
arXiv и текст внутри рисунков не попадают в текст без ручных регулярных выражений. Дополнительно:

- **формулы** распознаются в LaTeX (`do_formula_enrichment`);
- **уровни заголовков** восстанавливаются встроенным шагом docling по закладкам PDF, нумерации
  и стилю шрифта;
- **список литературы** удаляется (приложения после него сохраняются);
- **диакритика** склеивается: `Pl ¨ucker` → `Plücker`.

Результат: `data/markdown/<id>.md` (YAML-шапка с метаданными, маркеры `<!-- page: N -->` перед
каждой страницей) и `data/docling/<id>.json` для docling-чанкера. Разбор четырёх статей на GPU
занимает ~16 с.

### 3a. Чанки

| Сплиттер | Как режет |
|---|---|
| `markdown` | разделы h1–h3, внутри длинного раздела — окно по токенам |
| `recursive` | окно по токенам по всей статье, заголовки остаются в тексте |
| `docling` | `HybridChunker`: элементы документа объединяются под общими заголовками |

- Размер и overlap считаются в токенах одного токенизатора (bge-m3) для всех конфигураций.
- **Заголовок в тексте для векторизации**: `название статьи | раздел > подраздел`. Его длина
  ограничена 64 токенами и резервируется внутри `chunk_size`, поэтому текст для эмбеддинга
  никогда не превышает заданный размер.
- **Страницы** чанка берутся из маркеров страниц (markdown, recursive) или из координат
  элементов docling.
- **Карточка статьи**: один дополнительный чанк на статью из метаданных (авторы, даты, ссылка)
  для вопросов о самих статьях.
- Сборка называется по параметрам, например `markdown-800-100-h`, и хранится в
  `data/chunks/<имя>/` (`chunks.jsonl` + `config.json` со статистикой).

### 3b. Эмбеддинги

Модель **bge-m3** за один проход даёт dense-вектор (1024) и sparse-веса слов. Sparse-веса
многоязычные: русский вопрос активирует английские термины, в отличие от BM25. Длина каждого
входа проверяется токенизатором модели до векторизации — слишком длинный чанк останавливает
сборку, а не обрезается молча.

Результат: `data/index/<чанки>__<тип>-bge-m3/` — `dense.npy`, `sparse.jsonl`, `config.json`.

### 4. Qdrant

Коллекция `lab2-<индекс>`: dense-вектор (cosine, HNSW `m=16`, `ef_construct=100`) и
sparse-вектор (скалярное произведение весов bge-m3). Пороги индексации снижены до минимума
(10 KB), иначе Qdrant не строит HNSW для маленькой коллекции. Опционально — квантование int8.

Загрузка идемпотентна: в метаданных коллекции хранятся параметры схемы и отпечаток данных.
Совпадают — загрузка пропускается; данные изменились — точки перезаписываются, лишние удаляются;
изменились HNSW или квантование — нужен `--drop-and-reindex`. Сброс: `--reset`, `--reset-all`.

### 5. Поиск

- **dense**, **sparse** или **hybrid**; hybrid считает `dense + 0.3·sparse` на стороне Qdrant
  одним запросом (`FormulaQuery` над двумя prefetch);
- `ef_search` (`hnsw_ef`) и точный поиск без HNSW задаются при запросе;
- русский вопрос переводится на английский LLM (temperature 0, только при наличии кириллицы);
- вопрос длиннее 512 токенов отклоняется с понятным сообщением; так же проверяется его перевод,
  а обрезанный по лимиту перевод считается ошибкой, а не используется для поиска.

### 6. Ответ с цитатами

1. топ-5 фрагментов из поиска;
2. промпт: инструкции + фрагменты с метками `[F1]…[F5]` (название, раздел, страницы) + вопрос;
3. **проверка бюджета контекста** — промпт рендерится шаблоном чата модели и токенизируется самим
   llama-server (`/apply-template`, `/tokenize`); подсчёт совпадает с `usage.prompt_tokens` сервера
   до токена. Промпт + 1024 токена на ответ должны поместиться в контекст сервера (8192);
   иначе отбрасываются фрагменты с конца выдачи. llama-server запускается с `--parallel 1`:
   слоты делят один KV-кэш, и параллельные запросы вместе могли бы превысить контекст;
   при нескольких слотах выводится предупреждение. Ответ, обрезанный по лимиту токенов,
   помечается в результате;
4. вызов LLM из лабораторной №1 — Ministral-3-8B через llama-server (OpenAI API);
5. цитаты: из ответа извлекаются метки `[Fn]`, для каждой — статья, авторы, ссылка, раздел,
   страницы и сниппет (предложение фрагмента, ближайшее по смыслу к утверждению ответа, bge-m3).

Метки `[Fn]` вместо `[n]` выбраны потому, что в тексте статей есть собственные ссылки на
литературу вида `[7]`, которые модель иначе копирует в ответ.

## Оценка retrieval

Фрагмент релевантен, если содержит фразу-доказательство (сравнение без пробелов, фигурных скобок
и стилевых команд LaTeX). Метрики:

- **R@k** — доля фраз-доказательств вопроса, найденных в топ-k;
- **P@k** — доля фрагментов топ-k, содержащих фразу-доказательство;
- **MRR** — 1 / ранг первого релевантного фрагмента.

У вопроса 1–3 релевантных фрагмента, поэтому P@5 и P@10 малы по построению (≈ 0.2 и 0.13).

Итоговая конфигурация: `markdown`, 800 токенов, overlap 100, заголовки в чанке, hybrid bge-m3,
перевод запроса. Каждая строка меняет один параметр.

| Конфигурация | Чанков | ru R@5 | ru R@10 | ru P@5 | ru P@10 | ru MRR | en R@5 | en R@10 | en P@5 | en P@10 | en MRR |
|---|---|---|---|---|---|---|---|---|---|---|---|
| **итоговая** | 92 | 0.929 | 0.952 | 0.238 | 0.129 | 0.825 | 0.881 | 0.952 | 0.229 | 0.133 | 0.820 |
| только dense | 92 | 0.881 | 0.929 | 0.219 | 0.129 | 0.744 | 0.833 | 0.929 | 0.219 | 0.129 | 0.794 |
| только sparse | 92 | **0.952** | 0.952 | 0.248 | 0.124 | 0.761 | **0.929** | 0.952 | 0.238 | 0.129 | 0.827 |
| без перевода запроса | 92 | 0.833 | 0.952 | 0.210 | 0.129 | 0.710 | 0.881 | 0.952 | 0.229 | 0.133 | 0.820 |
| без заголовков в чанке | 88 | 0.762 | 0.929 | 0.200 | 0.129 | 0.693 | 0.810 | 0.929 | 0.219 | 0.133 | 0.675 |
| recursive-сплиттер | 63 | 0.833 | **0.976** | 0.248 | 0.152 | 0.690 | 0.833 | 0.929 | 0.248 | 0.148 | 0.712 |
| docling-сплиттер | 99 | 0.889 | 0.937 | 0.248 | 0.133 | **0.845** | 0.889 | 0.937 | 0.248 | 0.138 | **0.844** |
| чанк 400 / overlap 60 | 164 | 0.897 | 0.913 | 0.248 | 0.129 | 0.721 | 0.841 | 0.913 | 0.229 | 0.129 | 0.712 |
| точный поиск без HNSW | 92 | 0.929 | 0.952 | 0.238 | 0.129 | 0.825 | 0.881 | 0.952 | 0.229 | 0.133 | 0.820 |
| HNSW, `ef_search = 8` | 92 | 0.929 | 0.952 | 0.238 | 0.129 | 0.825 | 0.881 | 0.952 | 0.229 | 0.133 | 0.820 |

**Выводы**

- Заголовок в тексте чанка — обязательный элемент: без него чанк с гиперпараметрами не отличить
  от похожего чанка соседней статьи.
- Перевод запроса окупается: +0.115 MRR на русских вопросах за ~240 мс; английские вопросы
  не меняются.
- 800 токенов лучше 400: вероятно, при 400 факт и его контекст чаще оказываются в разных чанках.
- `recursive` хуже `markdown`: вероятно, окно на всю статью смешивает соседние разделы в одном чанке.
- HNSW на 92 векторах не влияет на качество: точный поиск и `ef_search = 8` дают ту же выдачу.
  Поиск занимает ~12 мс, почти всё — эмбеддинг вопроса.
- Различия меньше ~0.04 по R@5 соответствуют одному вопросу из 24.

Итоговой выбрана конфигурация `markdown 800/100 + hybrid + перевод` как лучшая по R@5 на русских
вопросах; docling-сплиттер — равноценная альтернатива с лучшим MRR.

## Проверка парсинга формул

Фразы-доказательства формульных вопросов взяты из LaTeX-исходников статей и сравниваются с текстом
после docling.

| Вопрос | Формула | Результат парсинга | Ранг в выдаче |
|---|---|---|---|
| Q19 | функция потерь D3D-VAE (выносная) | точно | 2 |
| Q20 | ошибка поворота `R_dist`, ViewCrafter (выносная) | точно | 4 (ru), 7 (en) |
| Q21 | ошибка смещения `T_dist`, ViewCrafter (выносная) | индекс `gt` распознан как `g^{t}` | — |
| Q22 | масштабирование LoRA, DreamPainter (выносная) | точно | 1 |
| Q23 | порог `s = 1/512`, Direct3D (строчная) | в тексте `s = 1 512` | — |
| Q24 | `u′ = u − W/2`, ViewCrafter (строчная) | в тексте `u- W2` | — |

Модель распознавания формул docling работает только с выносными формулами: строчные остаются
текстом, и дробь теряет черту. Распознанные формулы находятся хуже обычного текста (MRR 0.55–0.58):
чанк с LaTeX слабо похож на вопрос, сформулированный словами, и без заголовка в чанке R@5 по
формульным вопросам падает до 0.33.

## Пример ответа

```
$ python rag.py "Какое соотношение позитивных и негативных примеров использовалось в Preserving Product Fidelity?"

В работе использовалось соотношение 2:1 позитивных к негативным примерам … [F1]

[F1] Preserving Product Fidelity in Large Scale Image Recontextualization with Diffusion Models (Ishaan Malhi et al.)
     — 2 METHOD > 2.1 SYNTHETIC DATA AUGMENTATION, p. 2, 3
    http://arxiv.org/abs/2503.08729v1
    «We observe that a 2:1 positive:negative image ratio produced higher image quality and fidelity at the cost of diversity.»

Tokens: prompt 1868 + answer 88 of 8192 context; fragments dropped to fit: 0
```

Промпт с пятью фрагментами занимает 1 300–3 100 токенов из 7 168 доступных (8 192 минус резерв на
ответ). KV-кэш под контекст выделяется при запуске llama-server, поэтому запрос, прошедший проверку
бюджета, не увеличивает расход видеопамяти: Ministral-3-8B с контекстом 8192 занимает ~6 ГБ из 12.

Вопрос вне корпуса («Какая погода будет завтра в Москве?») получает ответ, что во фрагментах нет
такой информации.

## Ограничения

- Строчные формулы теряют двумерную вёрстку (см. выше); в четырёх заголовках docling склеивает
  слова (`RelatedWork`).
- Перевод запроса при temperature 0 всё же немного различается между запусками llama-server:
  MRR русских вопросов колеблется в пределах ~0.01.
- Качество самих ответов (ключевые факты, верность цитат) автоматически не оценивается; в примере
  выше модель добавила к верному ответу примечание, противоречащее цитате.
